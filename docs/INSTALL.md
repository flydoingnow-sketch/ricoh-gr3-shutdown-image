# 普通用户安装与恢复

## 准备

- 普通理光 GR III，菜单实际显示 Ver.2.10。本教程不涵盖官方固件升级；需要升级时按理光官方对应机型说明操作。
- 电量充足的电池、已备份照片的存储卡（建议备用卡）、读卡器、电脑。
- 电脑端工具，或 Python 3.10+、Tk、Pillow 的源码启动方式。
- 自己有权使用的 PNG/JPEG/WebP 图案。简单标志、纯色背景更容易在7264字节内保持清晰；不保证任意照片都能编码成功。
- 电脑上的长期备份目录，和每次操作包目录。不要把它们放在卡上作为唯一备份。

目前 Mac 应用未做 Developer ID 签名/公证，系统可能提示来源验证。只在你确认下载来源和文件校验值后，使用系统允许打开该应用的正常方式，不关闭系统安全功能。Windows 暂未在本地构建或实测，自动构建配置已提供。

## A. 首次备份原图

1. 确认相机还是原始理光关机图片。已经修改过的机身须找回当初两份原图，不能把当前品牌图当作理光原图。无法提供匹配原图时停止本工具流程。
2. 打开工具，点“1 生成原图导出包”，选择一个新的电脑目录。
3. 复制生成目录 `card` 内的两份入口文件与 `script` 文件夹到存储卡根目录。根目录应是：

```text
DCIM/                  原有照片目录
RICOH/                 原有相机目录（如有）
00078350.588
DEVELOP.MOD
script/startup.ttl
```

不要把外层 `card` 放进去。不要同时放固件升级 `.bin`。如果卡上有旧 `startup.ttl`，先保存到电脑并移走。

4. 安全弹出存储卡，插入相机。关机状态按住 MENU，再按电源进入工厂菜单。只把 `FW Setting1` 下的 `Script Enable` 打开。Camera Mode 保持 Normal；不要操作校准、镜头、电池或其他测试设置。
5. 关机，再正常开机（不按 MENU）。等待拍摄界面和读写灯停止，再关机取卡。
6. 卡根目录应有 `G3READ1.JPG`、`G3READ2.JPG`。复制到同一个电脑目录，在工具“电脑原图备份目录”选择它，点“2 校验原图”。两份均须完整7264字节且与参考哈希匹配。
7. 如缺文件、不是普通 GR III 2.10 或哈希不同，保留文件并停止，不用填充或裁切“修复”。

## B. 选择图片并检查最终画质

1. 保留电脑原图目录的选择，选择“自定义图片文件”。
2. 默认勾选“缩小上移，预留下方计数栏”。按原图选合适背景色，例如 `#151515`；红底图应输入与图案相近的红色，避免黑框。透明图会合成到所选背景。
3. 点“3 选择图片并编码”，选择新的电脑候选目录。编码最多约45秒，不保证成功。
4. 检查工具显示的最终 JPEG，以及目录内 `candidate.jpg`。看文字是否清楚、红底是否有杂块、下方是否留空。编码成功并不意味着观感好；不满意时换更简单图稿或调整布局。

## C. 默认的分步安装

1. 选择候选目录，点“4 生成临时导入包”，选择新操作包目录。它有 `card`、`recovery`、`candidate.jpg`、`manifest.json`。
2. 将 `card` 内文件复制到卡根目录，替换 `script/startup.ttl`。根目录只放当前操作包的一份脚本；不要复制 recovery。
3. 保持 Script Enable 开启，正常开机一次，读写停止后关机。**此时仍显示旧图，这是临时导入步骤的正常结果。**
4. 把本次新产生的图片和日志复制到电脑单独目录。具体名称在 `manifest.json` 的 `names` 中；每包不同。不要凭旧教程中的 M2/M6 文件名猜。
5. 工具“操作包目录”选择第1步生成的目录，“读回文件目录”选第4步目录，点“5 校验并生成写入包”。成功才得到新的正式写入包。
6. 用新写入包的 `card` 内文件替换卡上脚本和空日志。正常开机一次，等读写停止后关机，观察新的关机图。
7. 把最终产生的文件复制到电脑。选择写入包和最终读回目录，点“6 校验最终读回”。需日志无错误、最终图完整哈希与候选图一致。
8. 最后按 E 节关闭脚本，再正常开关机。文件校验通过仍须用户确认实际显示及正常使用。

## D. 实验组合包

界面的“一次开机导入并替换”把 C 的两个脚本连接起来。它会先备份当前图，再导入候选图，前段报错则退出；正常情况下直接覆盖并最终导出。

这一包装未在相机上整套实测，且没有中间电脑完整哈希验证。首次公众使用推荐 C。组合包仍必须最终读回校验，也不能把开启脚本、电脑复制或相机开机全部省掉。

## E. 结束与清理

1. 保存操作包、原图、全部本次读回和日志到电脑。
2. 从卡上移走 `script/startup.ttl`。空 `script` 文件夹可留可移，不影响相机照片。
3. 暂时保留 `00078350.588`、`DEVELOP.MOD`，按住 MENU 开机，将 Script Enable 关闭。
4. 正常开关机确认后，将两份入口文件、旧日志和实验读回移到电脑保存。保留 `DCIM`、`RICOH`。工具不会自动删你的卡内文件。
5. 不要删机内备份；每次更换保留独立备份，资源空间是有限的，目前没有自动机内清理功能。

## F. 恢复

每个临时导入/组合操作包内的 `recovery/card` 是**恢复该次修改前图片**的独立包。若此前已是麦当劳，它恢复麦当劳，不必然恢复最初理光图。要回到最初理光，应使用第一次从理光修改时创建的恢复包。

1. 确认对应那次备份确实建立过，保留原操作包和读回验证记录。
2. 只复制该 `recovery/card` 内的文件到卡根目录，替换脚本，不能和安装包一起复制。
3. 开启 Script Enable，正常开机一次，等读写停止后关机。
4. 按恢复 manifest 给出的 `log`、`readback` 名称保存输出；日志需 error=0，恢复图哈希应与那次安装的旧图备份一致。随后按 E 关闭脚本。
5. 恢复脚本本身及恢复流程仍需相机实测。没有正确备份、读写异常或断电时，不能承诺恢复成功。

## 常见问题

- MENU 开机进入拍摄：检查两个入口文件是否在卡根目录、型号版本是否正确、文件名和扩展名有无改变。不要去试其他工厂项。
- 卡上有新图但相机没换：如果运行的是临时导入包，这是预期行为；要先校验再生成写入包。
- 什么都没生成：检查 Script Enable、`script/startup.ttl`、本包空日志、是否已有同名输出。日志已被写入后不能直接清空重跑。
- 同名文件已存在：工具会停止，保留现场查日志；每次从工具生成新的操作包，不手改内部路径。
- 计数栏遮挡：勾选预留计数栏，缩小上移，不把张数和版本字画进背景图。
- 能否放两张图用 U1/U2 切换：本工具只替换一个资源文件，没有实现 U1/U2 切换。
- 为什么不能直接接 USB 自动刷：本项目没有验证可用的 USB 资源写入接口，电脑应用只是操作包生成器。
