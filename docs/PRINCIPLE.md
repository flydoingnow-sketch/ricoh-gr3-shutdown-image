# 原理：为什么可以更换关机图

## 不是重新制作官方固件

官方升级包是相机更新整套软件的通道；本项目使用的是固件里已有的工厂脚本入口。两个机制不同。能够安装官方固件，并不证明任何自制 JPEG 或脚本都能安装。

流程是：电脑准备图像和脚本 → 存储卡带入相机 → 已启用的 TTL 解释器执行文件操作 → 替换机内资源 → 相机按原来的显示代码读取资源。电脑没有直接修改官方固件，也没有用 USB 改写相机。

## 如何找到入口

分析样本为普通 GR III 2.10 的 `fwdc239b.bin`，SHA-256：

```text
d6a3c9c288d784080e7b283222ecdd8752adfeed6faa36dab44f73115354bfd4
```

固件内部版本 `2.10.21.27`，容器大小 30,391,780 字节，解包大小 59,718,388 字节。小端 32 位整包求和为 0 是格式校验结果，不能称为数字签名验证。

本次识别到 RTOS 向量起始解包偏移 `0x10870`，运行基址 `0x53000000`。相关代码使用文件名格式 `C:\%08ld.%03ld`；两个常量函数返回 78350 与 588，所以文件名是 `00078350.588`。文件内容为 `[OPEN_FACTORY_DEBUG_MENU]\r\n`。

另一份 `DEVELOP.MOD` 使用固件内的 10 字节序列：

```text
07 01 2c 1f 10 03 1e 16 05 2d
```

入口、MENU 开机操作和 `Script Enable` 在本次机身已经实测。正常开机读取的是 `C:\script\startup.ttl`，不是卡根目录的 `startup.ttl`。仅打开脚本设置，Camera Mode 维持 Normal，其他工厂设置不改。

关键地址：文件名格式化调用区约 `0x536BE8A4`；常量 getter `0x5381FE9C` 和 `0x5381FE4C`；10 字节比较区约 `0x536BF750`。这些地址只描述本次样本，不能拿到其他机型、固件照用。

## 替换哪一张图

此机身实际导出并匹配的路径是 `B:\Resource\Jpeg\GoodBye.jpg`。`B:` 为脚本可访问的内部资源盘，`C:` 为存储卡。这里的 `B:` 不是用户电脑里的磁盘盘符。

两次独立导出的原图完整一致，JPEG 规格为：720×480，8 bit，RGB，baseline，单扫描，4:2:0，7264 字节。原图 SHA-256：

```text
dff9ba0ad2c7ea2697b19470cf6c695337651ee0ef415a6d3359a7f318ff3c79
```

固件也含 `StartUp`、Urban 等资源。它们存在不表示普通 GR III 当前就使用它们，本项目不把这些图片混为一谈。

## 图片为什么必须处理

当前适配保留已经验证的 7264 字节规格、JFIF 信息、SOF0、SOS 和 marker 顺序。等长是本实现的兼容约束，不是已经证明相机绝不接受其他长度。工具不擅自放宽这个条件。

相同分辨率和 JPG 扩展名并不足够。普通 JPEG 可能使用渐进式、不同采样或不同结构。电脑端编码在限定质量与尝试次数内搜索量化表，不追加尾字节、不补 COM、不截断图片。复杂照片可能找不到合适结果，届时拒绝生成写入包。

后续质量修正保留 DC 量化项、不采用极端粗糙的色度设置，减少红底杂块。预览必须查看最终编码 JPEG，并通过实际相机显示确认；成功解码不是画质认可。

## 计数栏为何遮挡

图稿是背景资源，计数和固件版本属于相机自己的叠加显示。把这些文字画进图片会得到重复或错误的信息，也不能修改真实拍摄张数。

默认把输入图片等比放进 430×245 的上方区域，下方留约40%的背景。用户可选适合原图的纯色背景。这个布局来自本次遮挡反馈，仍需用相机显示位置确认；不能承诺适用于所有显示模式。

## 如何写入和检查

1. 在机内创建新的备份文件，保存当前 `GoodBye.jpg`。
2. 新建临时图文件并扩展到 7264 字节；本次机身的扩展零字节行为已验证。
3. 脚本把 JPEG 的非零字节以 `#数值` 形式写入，零字节保留为扩展结果。每段最多42字节，使解释器每行小于256字符。
4. 把备份和临时图复制到卡上。电脑核对完整 SHA-256、可解码性和备份一致性。
5. 从机内临时文件复制到 `GoodBye.jpg`，再把最终文件复制到卡，电脑比较候选图的完整哈希。
6. 关闭 Script Enable；正常开关机确认显示。

脚本只检查存在、大小、属性等，不计算机内 SHA-256。同长度复制失败或内容损坏可能绕过大小检查，因此最终读回不可省略。异常分支会尝试复制本次旧图回去，但相机断电、底层写入故障等仍不能保证自动恢复。
